# server2 — новый игровой сервер (TypeScript, протокол v2)

Решение пользователя (29.10.2026): новый сервер с нуля на другом движке — **TypeScript / Node.js**, **свой протокол**
(не протокол 2014: без пространств, объектов и моделей Flash), **прежние MariaDB и JSON-конфиги** (аккаунты, гаражи,
предметы, карты), **переход параллельно**: server2 работает рядом со старым сервером (`src/scripts`, Python) и
заменяет его, когда догонит по возможностям. Flash-клиент с server2 не работает — только html5.

## Почему TypeScript
- Тот же язык, что у html5-клиента: сервер импортирует общий код из `html5/src` — протокол (`net2/protocol.ts`),
  а дальше физику (1:1 из Flash), разбор карт, оружие и синхронизацию v2. Сервер считает то же, что клиент, тем же
  кодом — расхождений между ними нет, а движение и попадания можно проверять физикой на сервере.
- Один поток событий на процесс: нет гонок старого сервера (команды в отдельных потоках, перемешанные байты в
  сокете, двойное открытие разделов). Тяжёлое (bcrypt, позже физика боёв) — в `worker_threads`.
- Без зависимостей npm (пользователь разрешает скачивание только по запросу): свой WebSocket (как `html5/server/bridge.mjs`),
  свой клиент MariaDB (`src/db/mysql.ts`), свой bcrypt (`src/auth/bcrypt.ts`, проверен против Python `bcrypt`).
  Сборка — esbuild из `html5/node_modules` в один файл `dist/server2.mjs` под Node 18 (Debian i686).

## Протокол v2
WebSocket, путь `/ws2`. Текстовые кадры — JSON, двоичные — поток боя (этап 3: состояние танка, снапшоты — формат
синхронизации v2, `html5/docs/SYNC_V2.md`). Типы — `html5/src/net2/protocol.ts` (общий файл клиента и сервера).

- Каждое сообщение — объект с полем `t` (тип).
- Запрос клиента: `{"t":"auth.login","id":7,...аргументы}` → ответ `{"t":"reply","id":7,"ok":true,...данные}` или
  `{"t":"reply","id":7,"ok":false,"error":"wrong_password","message":"..."}`. `id` — номер запроса клиента.
- Событие сервера (без запроса): `{"t":"user","user":{...}}`, `{"t":"lobby.battle","battle":{...}}`, `{"t":"kicked",...}`.
- Первый запрос — `hello {version}`; другая версия протокола → ошибка `version`.
- Сервер шлёт ping раз в 15 с, без входящих данных 45 с — соединение закрывается. Текстовое сообщение — до 64 КБ,
  частота — до 40 сообщений в секунду (всплеск до 120), иначе закрытие.

### Этап 1 (готов: вход, регистрация, профиль, список боёв)
| запрос | аргументы | ответ |
|---|---|---|
| `hello` | `version` | `server`, `version` |
| `auth.register` | `username`, `password` | `user` |
| `auth.login` | `username`, `password` | `user` |
| `lobby.battles` | — | `battles` (и подписка на изменения) |
| `lobby.create` | `name`, `mode`, `mapId`, `maxPeople`, `timeLimitSec`, `scoreLimit`, `minRank`, `maxRank` | `battle` (только администратор) |
| `lobby.remove` | `battleId` | — (только администратор) |

События: `user` (профиль: имя, звание, очки, пороги звания, кристаллы, администратор), `lobby.battle` (бой
добавлен или изменился), `lobby.battleRemoved`, `kicked` (вход с другого места, бан).

Правила как у старого сервера: имя `[A-Za-z0-9_]{1,20}` (без учёта регистра — сравнение в базе), пароль 1–50
символов, bcrypt (`$2b$`, стоимость 12), бан из `dev/bans.json` (ник в нижнем регистре → время окончания в
секундах, 0 — навсегда) — для забаненного и неизвестного имени ответ `wrong_password`. Регистрация: `Users`,
`UserProperties` (стартовые кристаллы и очки из `server_properties.json`, роли `[0]`), строка `MountedItems` —
в одной транзакции. Звание — по порогам `src/scripts/client/ranks.py`. Администратор — роль 1. Повторный вход того
же игрока закрывает прежнее соединение (`kicked`).

Бои server2 хранит в своей таблице `S2Battles` (создаётся сама; таблица `Battles` старого сервера не трогается).
Пока таблица пуста, создаются бои по умолчанию.

v2), к клиенту PONG, SNAPSHOT (20 Гц, чужие живые танки) и CORRECTION.

Сервер — `server2/src/battle/`: `mapData.ts` (точки спавна из `configs/maps/<map_xml>`, z + 100; зоны смерти из
maps.json; папка карты клиента), `loadout.ts` (надетые корпус/пушка/краска с уровнями улучшений: HP = hull_armor,
урон, крит, ослабление, защита краски), `battle.ts` (бой), `rooms.ts` (идущие бои, счётчики игроков в лобби).
Правила — как у старого сервера: состояние своего танка — проверка жизни, порядка, скорости (три нарушения подряд —

союзник, в истории на `viewTime` не дальше 4 м (иначе 15 м + путь); урон Смоки from…to, крит, ослабление по
расстоянию; рельса — после зарядки, цели по расстоянию, каждая следующая × weakening_coeff; снаряд Твинс — одна
цель один раз; защита краски `<пушка>_resistance`; смерть, когда округлённое HP = 0; за уничтожение — kill_score
очков (только в статистике боя, в профиль пока не пишется), в TDM — очко команде; самоуничтожение статистику не
меняет. Тайминги — `server_properties.json` (`tank_spawn_delay_in_ms`, `tank_activation_delay_in_ms`,
`tank_dead_time_in_ms`). Клиент — `html5/src/net2/S2Battle.ts` (по образцу NetBattle: ServerClock, StateBuffer,
RemoteTank, эффекты оружия, таблица игроков, череп самоуничтожения).

### Этап 3, второй шаг (30.10): раунды, фонд, итоги и награды
Правила — как у старого сервера (`statistics_global_model`, `battle_fund_calculator`, `user_property_model`):
- **Раунд** идёт от входа первого игрока; конец — по `time_limit_in_sec` боя, в DM ещё и когда убийства лидера
  достигают `score_limit` (у старого сервера лимит в DM считается по убийствам; у TDM лимита нет). Пока идут итоги,
  `battle_field.active = false`: выстрелы, спавн, готовность и самоуничтожение не принимаются.
- **Фонд**: 100 в новом бою, +`kill_fund` (1) за уничтожение, в новых раундах начинается с 0. Делёж
  (`shareFund`/`splitTeamFund` — точный порт `battle_fund_calculator`): доля `score^1.5`, остаток — лидеру; в TDM
  сначала между командами (`blue = int(blue/red · fund · 0.25)`, остальное победителю, при равенстве пополам).
- **Награды**: фонд — кристаллами в конце раунда (`give_fund_to_users`); опыт за уничтожение (`kill_score`) пишется
  в профиль сразу, при новом звании — кристаллы за него (`RANK_REWARDS`). Начисления по игроку идут очередью, после
  каждой — событие `user` (кристаллы, опыт, звание).
- События: `battle.fund` (фонд изменился), `battle.roundEnd` (results: kills/deaths/score/reward по игроку, фонд,
  счёт команд, `timeToRestartSec`), `battle.restart` (танки уходят с поля), `battle.roundStart` (`timeLeftSec`,
  `teams` — после смены команд в TDM). В `BattleInfo` добавлены `fund` и `roundEndInSec` (вход во время итогов).
- Рестарт: через `round_end_screen_time_in_sec` (10 с) — фонд 0, статистика игроков обнулена, в TDM команды меняются
  местами, танки ждут `battle.ready`. Пустой бой замирает: следующий вход начинает новый раунд с фондом 100.
- Клиент (`net2/S2Battle.ts`): `battle.roundEnd` — `TankDemo.finishBattle`, таблица итогов с наградой и отсчётом,
  таймер HUD на нуле; `battle.restart` — `restartBattle`, чужие танки снимаются (скин и заголовок живут дольше
  танка), `battle.roundStart` — новые команды, обнуление таблицы, таймер, `battle.ready`.
- Проверка: `node --experimental-transform-types html5/tools/server2-round-smoke.ts <ws>/ws2` — всё прошло (30.10,
  Debian): формулы фонда, убийство (фонд 100→101, опыт +10), итоги (101 кристалл), рестарт, спавн нового раунда,
  смена команд TDM.

### Этап 3, третий шаг (30.10): ящики и припасы
Правила — как у старого сервера (`battle_field_bonus_global_model`, `bonus_common_global_model`, `bonus.py`,
`tank_global_model`):
- **Зоны** — `bonus-region` из XML карты (`configs/maps/<map_xml>`): бокс `min`…`max`, `game-mode` и `bonus-type`.
  Типы: `armorup` → броня, `crystal` → кристаллы, `crystal_100` → золото, `medkit` → аптечка, `nitro` → нитро,
  `damageup` → двойной урон; неизвестные (`crystal_500`, `spin_box`, у Serpuhov `double_armor`/`gold`/`health`…) не
  выпадают. Как и старый сервер, зона без `game-mode` не регистрируется (у карты highland таких зон 15 — ящиков там нет).
- **Падение**: раз в `supplie_box_spawn_time_in_sec` (10 с) падает случайный припас (броня, аптечка, нитро, урон).
  Точка — случайная в зоне для режима боя; нет зоны нужного типа — ящик не падает. Срок жизни — `<тип>_box_life_time_in_sec`
  (броня 60 с, аптечка/нитро/урон 120 с, кристаллы 1200 с, золото 720000 с), потом `battle.bonusesRemoved`.
- **Золото и кристаллы**: на каждое изменение фонда `randint(1, gold_box_drop_probability) == 1` (в конфиге 1 — всегда)
  — сообщение `gold_notification_message` всем и через `gold_drop_time` (10 с) золотой ящик; ящик кристаллов — когда
  счётчик изменений фонда дошёл до `num_fund_changes_for_crystal_drop` (старый сервер счётчик не сбрасывает).
- **Подбор**: клиент шлёт `battle.takeBonus`, когда куб ящика (150) коснулся танка. Сервер проверяет, что раунд идёт,
  танк жив (заспавнен или активен) и ящик есть (расстояние старый сервер не проверял — так же и здесь). Ящик исчезает
  у всех (`battle.bonusTaken`), ящики убираются в конце раунда и при жизни срока.
- **Эффекты** (значки `EffectDescriptionModel`, 1 аптечка, 2 броня, 3 урон, 4 нитро): броня — получаемый урон ×0.5,
  урон — наносимый ×2, нитро — скорость, поворот корпуса, поворот башни и разгон ×`nitro_speed_coefficient` (1.3);
  все на `*_effect_time_in_sec` (60 с), повторное взятие обновляет время. Аптечка — 30 HP в секунду до полного
  здоровья или `first_aid_effect_time_in_sec` (40 с), повторно не берётся, пока действует. Золото — +1000 кристаллов,
  кристаллы — +10 (в профиль, событием `user`). Со смертью и в новом раунде эффекты снимаются.
- **Протокол**: в `BattleInfo` — `bonuses` (ящики на поле) и `bonusFallSpeed` (200); запросы `battle.takeBonus`,
  `battle.bonuses` (сверка после загрузки карты — события за это время клиент пропустил); события
  `battle.bonusSpawned`, `battle.bonusTaken`, `battle.bonusesRemoved`, `battle.effect`, `battle.spec` (нитро),
  `battle.goldNotify`, `battle.goldTaken`.
- **Клиент**: отрисовка ящиков вынесена в `tanks/bonuses/BonusField.ts` — её делят `BonusManager` (старый протокол)
  и `net2/S2Bonuses.ts` (server2): парашют, падение, посадка, подбор кубом, звук `bonus_take.mp3`. Эффекты —
  значки над своим (`TankDemo.showEffect`) и чужими (`UserTitle.showIndicator`) танками; нитро —
  `TankDemo.setSpeedFactor`/`RemoteTank.setSpeedFactor` (как SET_SPECIFICATION старого сервера); золото — сообщение
  `ui/hud/BattleNotice.ts` (звука золота в ассетах нет).
- **Проверка** (30.10, Debian): `node --experimental-transform-types html5/tools/server2-bonus-smoke.ts ws://127.0.0.1:5180/ws2`
  — всё прошло: разбор зон Silence (все шесть типов), ящик припаса виден обоим и берётся один раз, эффекты
  (нитро ×1.3 и `battle.spec`, двойной урон, аптечка 45→68 HP), несуществующий и уже взятый ящик не берутся,
  золото (сообщение, ящик через 10 с, +1000 кристаллов), ящик кристаллов на изменение фонда (+10), фонд 101.
  Прогоны случайно дали нитро, двойной урон и аптечку; броню и двойной урон в деле (урон ×0.5 / ×2) смоук
  не проверял — код общий с проверенными эффектами.

### Этап 3, четвёртый шаг (30.10): инвентарь, мины, чат, админ-команды и проверка физикой
- **Инвентарь боя** (клавиши 1–5: аптечка, броня, двойной урон, нитро, мина) — слоты из `server_properties.inventory`;
  `battle.activateItem {index}` проверяет, что танк жив и активен, припас есть и слот не на перезарядке, списывает
  `UserItems.count`, ставит `readyAt` и шлёт только игроку `battle.inventory` (счётчик и перезарядка). Эффекты —
  те же, что у ящиков (`battle.effect`, `battle.spec`). Счётчики при входе — в `BattleInfo.inventory`.
- **Мины**: применение мины кладёт её лучом вниз от точки танка +100 (`mine_offset_from_ground`), взводится
  `mine_activate_time_ms`; события `battle.minePlaced` / `mineActivated` / `mineExploded` / `minesRemoved`;
  взрыв наносит урон по площади (как `Mine.explode` старого сервера), мины убираются в конце раунда и при выходе
  владельца. Сверка после загрузки карты — `battle.mines`.
- **Чат боя**: `battle.chat {text}` → событие `battle.chat` всем (author, rank, kind: 0 игрок, 1 система, 2 ответ).
  Текст с `/` — команда администратора (`src/chat/commands.ts`): `help`, `kick`, `ban`, `unban`, `restart`,
  `crystals`, `exp`, `resetgarage`, `delbattle`; проверяется роль администратора (`UserProperties.user_roles`),
  ответы — только вызвавшему. Бан переживает переподключение (таблица банов старого сервера).
- **Лобби**: `BattleSummary.users` — кто сейчас в бою (ник, звание, убийства, команда), `lobby.battle`
  обновляется при входе и выходе игрока.
- **Проверка физикой**: сервер сверяет скорость из состояния танка с `hull_speed` своего снаряжения; после
  `VIOLATIONS_BEFORE_CORRECTION` (3) нарушений подряд отправляет `CORRECTION` с последним принятым сэмплом —
  телепорт и разгон отклоняются, клиент возвращает танк в принятое состояние (`S2Battle.onCorrection`).
- **Проверки** (30.10, Debian): `html5/tools/server2-chat-smoke.ts` — вход A/B, список игроков боя в лобби,
  сообщение игрока, отказ не-админу, `/help`, `/crystals`, `/exp`, `/ban` + `/unban` с переподключением, `/kick`,
  `/restart` + итоги, `/delbattle`; `html5/tools/server2-inventory-smoke.ts` — активация припасов, счётчики и
  перезарядка, мина на поле, отказ телепорту (CORRECTION). Оба прошли.

### Этап 3, пятый шаг (30.10): оставшиеся пушки с реальными характеристиками
Все 8 корпусов и 9 пушек M0–M3 уже в каталоге гаража (`configs/garage_items/*.json`) и сконвертированы в
`html5/public/tank_parts`; характеристики берутся из тех же конфигов, что у старого сервера, с уровнями улучшений.
- **Гром** (`thunder`): прямое попадание 27.6–38.2 без критов, сплеш 12 м с уроном 0 у края и 25 в центре,
  прямой целью не считается, стрелок тоже получает урон; дружественный огонь выключен. Событие `battle.thunder`.
- **Шафт** (`shaft`): удержание при полной энергии — прицел (расход 277/с, урон 47–110 по потраченной энергии,
  пробитие с `weakening_coeff` 0.24), короткий клик — аркада 20.4–27.8 на `fast_shot_energy`; пауза после
  прицельного выстрела 500 мс. Запросы `battle.shaftAim`, `battle.shaft`, событие `battle.shaft`.

## Запуск
- Сборка: `node server2/build.mjs` (проверка типов + `dist/server2.mjs` и `dist/bcrypt-worker.mjs`).
- Запуск: `node server2/dist/server2.mjs`, рабочая папка — `dev` (как у старого сервера: `configs/`, `bans.json`).
  Переменные: `PORT` (5290), `HOST` (127.0.0.1), `TANKI_DEV` (папка `dev`, по умолчанию текущая).
- Debian: `~/tanki/server2/dist/`, служба `tanki-server2` (`deploy/tanki-server2.service`: 127.0.0.1:5290, рабочая
  папка `~/tanki/dev`). Снаружи — через `/ws2` веб-сервера `html5/server/public-server.mjs` (и vite в разработке).
  Выкладка: `node server2/build.mjs`, скопировать `dist/server2.mjs` и `dist/bcrypt-worker.mjs`, `sudo systemctl restart tanki-server2`.
- Проверка: `node --experimental-transform-types html5/tools/server2-smoke.ts ws://хост:порт/ws2`.
